# Redis 运维规范

## 部署

### 开发环境

本地开发直接用 Docker 启动单节点实例：`docker run -d -p 6379:6379 redis:7.2`，开发环境不开启持久化。

### 生产集群部署

生产环境统一部署为 Cluster 模式：3 主 3 从，共 6 个节点，同一分片的主从节点必须分布在不同可用区。
版本统一为 7.2；持久化采用 AOF（appendfsync everysec），并在每天凌晨 3:00 额外生成一次 RDB 快照用于备份。
新集群上线前必须完成压测，单分片压测 QPS 不低于 5 万。

## 扩容

### 扩容触发条件

任一分片的内存使用率连续 3 天超过 70%，或者单分片 QPS 峰值超过 8 万时，需要发起扩容申请。

### 扩容步骤

扩容通过增加分片完成：先加入新的一主一从，再用 `redis-cli --cluster reshard` 迁移 slot。
slot 迁移只能在业务低峰期（凌晨 1:00–5:00）进行，单次迁移不超过 1000 个 slot。
扩容完成后需要观察 24 小时，确认各分片的内存和 QPS 已经均衡。

## 高可用

### 故障转移

主节点宕机后由集群自动完成故障转移，从节点通常在 15 秒内被提升为新的主节点。
故障转移完成后，值班人需要确认客户端已经刷新集群拓扑。

### 脑裂处理

发生主从网络分区时，可能出现两个主节点同时接受写入的脑裂问题。
团队统一配置 `min-replicas-to-write 1` 和 `min-replicas-max-lag 10`：没有可用从节点的主节点会拒绝写入。
网络恢复后以新主节点的数据为准，旧主节点在分区期间写入的数据需要人工核对后补录。
