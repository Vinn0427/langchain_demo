# MySQL 运维规范

## 部署

### 生产集群部署

生产环境统一使用 8.0 版本，采用一主两从架构，通过 MHA 实现主库故障时的自动切换。
主库和从库必须部署在不同机架上，所有从库开启 `read_only`。

## 扩容

### 扩容触发条件

单库数据量超过 2TB，或者单表行数超过 5000 万时，需要评估分库分表。

### 扩容步骤

读压力大时优先增加从库；写压力大时按用户 ID 哈希拆分为 16 个分库。
拆分前必须先在影子库完成全量数据校验，流量切换安排在周二或周四凌晨进行。

## 备份与恢复

### 备份策略

每天凌晨 2:00 使用 xtrabackup 做一次全量物理备份，binlog 实时归档，备份文件至少保留 14 天。

### 恢复演练

每个季度至少做一次恢复演练，要求 1TB 数据在 4 小时内完成恢复。

## 主从延迟

从库复制延迟超过 30 秒触发告警；延迟超过 300 秒时，读流量自动切回主库。
